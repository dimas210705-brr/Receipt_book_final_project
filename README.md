## О проекте
Приложение для поиска рецептов, ведения персональных кулинарных коллекций, личных заметок к блюдам и автономной работы без доступа к сети (Offline-First).

Стек проекта:
- **UI:** Jetpack Compose, Material 3, Navigation Compose
- **Архитектура:** Clean Architecture / MVVM, Unidirectional Data Flow (UDF)
- **Реактивность:** Kotlin Coroutines, Flow, StateFlow, SharedFlow
- **Локальные данные:** Room (SQLite) + Jetpack DataStore Preferences
- **Фоновые задачи:** WorkManager + Hilt Worker
- **Сеть:** Retrofit, OkHttp, Gson
- **DI:** Dagger Hilt
- **Изображения:** Coil Compose

Используемое API: [Spoonacular API](https://spoonacular.com/food-api/docs)
- `GET /recipes/complexSearch?query=` — поиск блюд по названию
- `GET /recipes/{id}/information` — получение ингредиентов блюда по id
- `GET /recipes/{id}/analyzedInstructions` — получение шагов приготовления по id

API-ключ прописывается в `api/ApiKey.kt`.

## Что сделано в Финальном проекте

Приложение развито из простого клиента API в **персонализированный offline-first mini-product**: добавлена персональная часть пользователя (кукбуки, заметки, рейтинги), полноценное локальное кэширование рецептов с политикой устаревания (TTL), экран истории, экран настроек на DataStore и фоновая предзагрузка через WorkManager.

### 1. Новые пользовательские данные

Хранение строго разделено по назначению:

#### DataStore Preferences (Настройки и предпочтения)
- `isAutoCacheEnabled` (Boolean) — флаг фоновой предзагрузки избранных рецептов для оффлайна.
- `isHistoryEnabled` (Boolean) — переключатель автоматического ведения истории просмотров.
- `cacheTtlHours` (Int) — срок жизни кэша рецептов (TTL) в часах (по умолчанию 24 ч.).

#### Room Database (Пользовательские данные и кэш)
- **`CachedRecipeEntity`** — локальная копия полного рецепта (ингредиенты, шаги, кухни в JSON) с метаданными: метка времени кэширования (`cachedAtTimestamp`) и флаг закрепления (`isPinnedOffline`).
- **`RecipeCollectionEntity`** — персональные коллекции/кукбуки пользователя (*«Завтраки»*, *«Праздничный стол»* и др.).
- **`RecipeCollectionCrossRef`** — связь Many-to-Many между коллекциями и рецептами со временем добавления.
- **`RecipeNoteEntity`** — персональные заметки пользователя к конкретному рецепту: текст заметки, личный рейтинг (1–5 звёзд), статус «Приготовлено» (`isCooked`), дата обновления.
- **`RecipeHistoryEntity`** — история просмотренных рецептов с временной меткой (`viewedAtTimestamp`).

### 2. Новые пользовательские сценарии

Реализовано 4 сквозных законченных пользовательских сценария:

1. **Персональные кукбуки (коллекции) и личные заметки к рецептам:**
   - Пользователь создает собственные коллекции блюд с произвольным названием и описанием на вкладке **«Кукбук»**.
   - На экране детального просмотра рецепта пользователь может записать персональную заметку (секреты приготовления, корректировка пропорций), поставить личный рейтинг звёздами и отметить блюдо как «Приготовлено». Все изменения сохраняются локально в Room и доступны без интернета.

2. **Полноценный Offline-First с политикой актуальности (TTL):**
   - При открытии любого рецепта данные берутся напрямую из локального кэша Room (*Single Source of Truth*).
   - Если кэш отсутствует или его возраст превысил TTL (настраивается в часах) и есть интернет — приложение обновляет данные из сети в фоне и перезаписывает кэш.
   - Если сети нет, но рецепт уже открывался или предзагружен — он открывается мгновенно и полностью (с ингредиентами и шагами) со специальным баннером: *«Офлайн-режим: рецепт сохранён в локальном кэше»*.

3. **История просмотров (Recent) с быстрым доступом:**
   - Открытие любого рецепта автоматически регистрируется в таблице `recipe_history` (если опция включена в настройках).
   - Экран **«История»** отображает список просмотренных блюд в хронологическом порядке, позволяет повторно открыть рецепт даже без сети или очистить историю в один клик.

4. **Экран настроек (Settings):**
   - Управление параметрами приложения через DataStore Preferences: включение/отключение истории, автокэширования, а также кнопка принудительной очистки устаревшего оффлайн-кэша.

### 3. Как устроена Offline-First часть

- **Single Source of Truth:** Экран рецепта подписан на Flow из Room (`OfflineRecipeDao.observeRecipeById`). Сеть никогда не является единственным источником состояния UI.
- **Политика устаревания (TTL):** В `OfflineFirstRecipeRepository` при запросе проверяется условие:  
  `System.currentTimeMillis() - cachedAtTimestamp > ttlMillis`.  
  Если кэш свежий, дорогостоящие запросы к сети не выполняются.
- **Кэширование сложных структур:** Список ингредиентов и шагов сериализуется в JSON через `Gson` и сохраняется в SQLite, гарантируя полную автономность деталей рецепта.
- **Graceful Degradation:** При сетевой ошибке (нет интернета / таймаут) репозиторий не ломает экран, а возвращает сохраненную в Room версию рецепта.

---

### 4. Фоновая обработка через WorkManager

- **Класс воркера:** `OfflinePreloadWorker` (настроен с Hilt через `@HiltWorker`).
- **Зачем используется:** Автоматическая синхронизация и оффлайн-предзагрузка. Воркер находит все рецепты из Избранного и Коллекций и заранее скачивает их полные данные (ингредиенты, инструкции) в локальный кэш Room.
- **Где настроен:** В `RecipeBookApplication` при запуске приложения регистрируется периодическая фоновая задача `PeriodicWorkRequestBuilder` с интервалом раз в 12 часов с политикой `ExistingPeriodicWorkPolicy.KEEP`.

### 5. Реактивность и композиция Flow (ДЗ 6)

Состояние экрана поиска и фильтрации строится на реактивном объединении **4 независимых источников**:
1. `_searchQuery` (`MutableStateFlow`) — текстовый ввод пользователя.
2. `_searchFilter` (`MutableStateFlow`) — выбранный режим фильтрации (*Все / Только в избранном / По алфавиту*).
3. `favouriteRepository.observeFavourites()` (`Flow`) — **Data Layer из Room**.
4. `_searchRetryTrigger` (`MutableSharedFlow`) — поток действий перезапроса поиска.

Применены операторы Flow:
- `debounce(400)` — защита от спама API при вводе текста.
- `distinctUntilChanged()` — исключение дублирующих запросов.
- `flatMapLatest` — отмена предыдущего незавершенного сетевого запроса при новом вводе.
- `combine` — объединение результатов сети, данных Room и фильтров. Добавление блюда в избранное реактивно пересчитывает список без повторного похода в сеть.
- `stateIn` — удержание состояния экрана в виде `StateFlow<RecipeBookUiState>`.

### 6. Написанные тесты

Все тесты написаны в едином стиле проекта с использованием легковесных **Fakes** без сторонних библиотек мокирования:

#### Новые тесты финальной функциональности (`OfflineFirstRepositoryTest`):
- `getCachedRecipe_returnsMappedDomainRecipe` — проверка корректного маппинга кэшированной сущности из Room со всеми ингредиентами и кухнями в доменную модель.
- `refreshRecipe_whenNetworkFails_returnsCachedFallback` — проверка оффлайн-отказоустойчивости: при сбое сети репозиторий успешно отдает сохраненный кэш.
- `refreshRecipe_whenNetworkSuccess_updatesDao` — проверка сетевого обновления и записи свежих данных в локальную БД.

#### Unit-тесты ViewModel и Flow (`RecipeBookViewModelTest`):
- корректное начальное состояние ViewModel
- пустой поисковый запрос
- успешный поиск с проверкой `debounce`
- реактивная фильтрация «Только избранные» через `combine` без повторного обращения к API
- ошибка при поиске
- загрузка рецепта и retry через `SharedFlow`
- добавление и удаление из избранного

#### Тесты мапперов и потоков Room (`MapperTest`, `FavouriteFlowTest`):
- преобразование всех DTO в доменные модели
- обработка пустых списков ингредиентов
- проверка полных цепочек эмиссий Flow при изменениях в Room

#### UI & Интеграционные тесты (`NavigationIntegrationTest`, `RecipeDetailRetryIntegrationTest`):
- сквозная навигация Поиск → Детали с проверкой Compose UI
- обработка ошибки сети на UI и успешный Retry

## Как проверить финальную работу

1. **Проверка Offline-First:**
   - Откройте любой рецепт из поиска при включенном интернете.
   - Выключите Wi-Fi / мобильный интернет (или переведите эмулятор в Airplane Mode).
   - Вернитесь назад и откройте этот же рецепт снова (или перейдите во вкладку «История»).
   - Рецепт откроется полностью с ингредиентами и шагами, а сверху отобразится баннер оффлайн-режима.
2. **Проверка коллекций и заметок:**
   - Перейдите на вкладку **«Кукбук»**, создайте коллекцию (например, *«Ужины»*).
   - Откройте любой рецепт, напишите текст в блок «Моя заметка», поставьте 5 звёзд и отметьте чекбокс «Приготовлено».
   - Перезапустите приложение — заметка, рейтинг и статус останутся на месте.
3. **Проверка истории:**
   - Просмотрите несколько рецептов.
   - Перейдите во вкладку **«История»** — просмотренные блюда упорядочены по времени.
   - Нажмите кнопку корзины вверху — история очистится.
4. **Проверка настроек:**
   - Перейдите во вкладку **«Опции»**, измените переключатели или очистите кэш.
